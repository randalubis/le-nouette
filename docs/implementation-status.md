# Implementation Status

[← Product spec hub](./product-spec.md) · [← Technical spec hub](./technical-spec.md)

This is the single source of truth for what's actually built versus backlog in the Le Nouette app (`./app`), as of 8 October 2026. It is a separate axis from the decision-confidence labels used throughout the product and technical spokes (`LOCKED`/`ASSUMPTION`/`OPEN`/`DEFERRED` and `REQUIRED`/`PROPOSED`/`OPEN`/`DEFERRED`) — a `LOCKED` business decision or a `REQUIRED` technical rule can still be entirely unbuilt. Spoke docs point back here with a short `**Implementation: ...**` line; the narrative and evidence live here, not duplicated across spokes.

**Database note:** The app's runtime database connection uses Supabase project `xvbloiuwedrpcrjjusky` (`ordering-system-sg`, ap-southeast-1), not the value previously documented as `birojajosbxwkrxzepar`. This is configured via DATABASE_URL (.env.local, app/src/lib/db/schema.ts migrations applied). Vercel production was updated after migration 0000 landed; production DB is very likely the same but not directly confirmed.

### 0.9.0 (1 October 2026)

- **Referral capture on order success:** One-time native HTML dialog opens on the order success screen (Screen 3), asking "Siapa yang memperkenalkan Le Nouette ke kamu?" (EN: "Who introduced you to Le Nouette?"). Dialog is dismissed by selecting a referral source (chips: Teman, keluarga, Instagram, WhatsApp, Lainnya) + optional name/account field (max 60 chars, control chars stripped), Lewati (skip), or Escape. Dialog state is tracked client-side via localStorage key `le-nouette:referral-asked` so it is shown only once per phone number. Public server action `saveReferralAction({id, token, source, name})` records the referral via the order's public_token (same lookup as customer order tracking); whitelisted source enum prevents injection; set-once logic prevents overwrite; returns `{error}` only. New nullable columns: `orders.referral_source` (enum: Teman, keluarga, Instagram, WhatsApp, Lainnya, null), `orders.referral_name` (text, null). Founder order card displays "Referral: …" when present. Orders export (CSV/XLSX) gains `referral_source` and `referral_name` columns. Migration: `app/drizzle/0003_referral.sql`. Implementation: `app/src/lib/referral.ts` (public action), `app/src/components/storefront.tsx` (Screen 3 dialog), `app/src/lib/db/schema.ts` (columns), `app/src/components/order-board.tsx` (card display).
- **Export formula injection hardening:** All user-supplied text cells in CSV and XLSX exports are now prefixed with a single-quote apostrophe (`'`) if they start with `=`, `+`, `@`, tab, or CR characters. Prevents formula injection when the file is opened in Excel/Sheets. Applied via `safeText()` utility in `app/src/lib/export.ts`. Phone columns already apostrophe-prefixed in prior releases.

### 0.8.1 (1 October 2026)

- **WhatsApp message format:** Updated `waMessage()` to use multi-line layout with paragraphs separated by blank lines. Order details now displayed as a block (Pesanan *id*, items as bullet-list, total, date, fulfillment/refund details) instead of inline. Improved readability in WhatsApp thread.
